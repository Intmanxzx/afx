# 精度复核

分阶段执行器为每个 case 生成一次 CPU 参考。目标输出落盘、释放 NPU 后，CPU worker 按现有 dtype 容差逐元素比较；任一元素失败即失败，不按通过比例放行。NaN 不相等，同号 Inf 相等，整数和布尔值精确相等。

AF-MLIR、AF-Legacy 和 Triton-NPU 对 CPU 精度失败时，按设备复用或创建一次 EagerNPU 执行。EagerNPU 使用 `torch.compile(backend="eager")`，与 Baize 单算子模式一致。它不是关闭 Autofuse 的 Inductor/UB 后端。辅助执行占用现有 worker/设备预算，独立保存执行记录，不增加原队列任务完成数。

复核比较目标输出和 EagerNPU 输出，不重新执行 CPU 或目标。最终标杆使用已有 `accuracy_ref` 字段；CPU 首比和 EagerNPU 复核都保存在 `detail.accuracy_evidence`。基线运行失败时保留 CPU 失败及基线执行 UUID，不能转为通过。平台复测上传包含辅助记录，完成回执仍对应原任务。旧记录不补造证据，重新执行后自然产生新证据。

每个输出记录绝对/相对误差、均值、RMSE、超容差倍数、NaN/Inf 失败数量、错误比例和连续段数。零参考值不进入相对误差最大值计算。空间形态按逻辑展平顺序分为整片、连续、等间隔、分散；超过 65536 个错误元素时不展开坐标判断等间隔。它不代表物理内存布局，也不推断根因。

新精度 issue 签名包含主算子类别、异常性质、超容差强度、错误比例、粗形态。dtype、比较关系及计算特征（如静态/动态、elementwise）不进入签名。旧记录没有这些指标时沿用原分类。误差强度用于聚类，不直接判定根因是舍入误差还是实现错误。
