# 百万级服务端存储设计

状态：设计与实现中，尚未证明百万级容量，禁止据此部署或宣称优化完成。

## 规模与口径

分别统计 workload、执行轮次、backend attempt、Shape result 和阶段事件。百万个用例不等于百万行：两后端、三 Shape、重复执行会产生数倍结果及事件。容量评估同时覆盖百万 attempt 与百万 workload；报告数据库、索引、WAL、统计侧库及备份，不能只报告主表。随机新模型几乎无法内容去重，因此必须控制每条唯一记录的大小。

## 目标结构

1. 热事实：workload、attempt、shape_result、round_member、current_head。内部关联使用INTEGER键；外部UUID保留唯一映射。所有真实重试是独立事实，不能因为结果相同而合并执行次数。
2. 共享维度：source、environment、execution_config、evaluation、operator、dtype。执行配置不含batch、模型描述、诊断、telemetry等每次变化字段。JSON规范化摘要使用32字节BLOB唯一键，避免64字符十六进制在索引中重复。
3. 冷内容：模型case_spec、诊断、日志按内容摘要引用，按需读取并压缩。相同内容只存一次；摘要冲突必须核对内容。哈希以未压缩规范内容计算，不随压缩算法变化。初版优先SQLite BLOB以保持事务、备份原子性，不引入文件与数据库双写悬挂对象。
4. 查询模型：仅保存状态、数字、分类ID和事实ID；不再复制完整配置、版本JSON、模型metadata和日志。当前头表只存head指针；历史按seed/shape/arrival游标检索，不在每次请求执行全历史窗口函数。
5. 搜索：结构化字段使用组合索引；模型算子/dtype在workload维度建立倒排关系。文本搜索使用独立文档索引，仅索引确实可搜索的文字，不把metadata JSON复制到每个attempt。不默默改变当前查询表达式语义。
6. 汇总：增量维护带类型键的计数，变更队列按实体合并；避免每个seed持久化一份标签JSON贡献。重放/失败变通过时必须原子减旧加新。重建在影子表进行，完成后切换，不在请求路径全表聚合。
7. 修复与幂等：请求键、请求hash、操作结果引用与不可变版本持久化；相同key必须返回当时结果，不能直接返回后来变化的repair状态。共享快照/响应内容复用；不能通过任意删除幂等记录换空间而允许旧请求再次执行。
8. 调度事件：常用阶段时间、温度、资源峰值为类型化字段；依赖关系按ID引用，时钟domain/worker环境共用。保留策略明确区分诊断明细与长期计数；不把删历史当作无损去重。

## 写入与读取约束

上传单事务执行身份校验、不可变内容冲突校验、内容插入、事实插入、当前头和计数更新、回执ACK提交。JSON解析/哈希/压缩应在写事务前完成；事务中再次核对竞争条件。重复上传不触发重建或计数累加。普通详情GET不获取writer锁。分页以单调arrival为游标，不使用OFFSET；查询仅读取返回页需要的冷内容。每个索引必须有真实查询计划与写入成本依据。

## 分阶段落地

先收敛现有报表中的重复execution/evaluation/environment、搜索metadata和按Shape日志，在不改变HTTP响应与执行语义下建立存储预算。随后引入内部整数事实键、冷内容引用与窄历史/头表；最后替换全量projection和统计贡献结构。只保留当前规范化表的查询视图，不提供旧库迁移或旧协议适配。

本次允许从空库部署，但旧库不能由新程序静默改写；旧备份保留对应版本恢复入口。客户端必须使用新身份/同步epoch，防止旧结果回灌清空后的中心。

## 验收门槛

- 同一数据集优化前后：总磁盘、每workload/attempt/shape字节、每个表及索引页、WAL峰值。分别测试高重复与低重复内容，不能只用相同小夹具夸大节省。
- 1万、10万、100万规模阶梯，记录硬件、样本数、P50/P95/P99、吞吐、超时、RSS、FD。数据生成须经过真实入库；直接SQL造数只用于单独标记的查询容量测试。
- 当前页、历史页、失败过滤、算子/dtype搜索、统计、领取、续租、复测、归档及上传混合负载；保存EXPLAIN QUERY PLAN。
- 未过滤首页/历史分页不能随全历史线性扫描；统计缓存查询不能为了刷新持有长写事务。具体延迟预算以oracle1实测基线制定。
- 丢ACK重试、请求冲突、多后端完整轮次、缺Shape、接管、中心/客户端重启与断网；结果、回执、计数和修复关联不丢失、不重复。
- 冷内容备份恢复、压缩损坏和hash不一致必须失败关闭，不返回伪造的完整结果。
