# 测试记录聚合与批量复测设计

日期：2026-11-12。本文直接替换早期“原记录定向覆盖”设计，以下为唯一当前口径。

## 1. 产品规则

- 外层按完整 seed + shape_index 全站聚合，不包含用户、环境、后端。
- 一条测试记录是同一次测试的多后端结果；不能拼接不同测试轮次。
- 当前主后端固定 AF-MLIR。随机批测和网页复测均包含 AF-MLIR；不实现主后端选择。
- 当前记录是中心最后首次入库、且所有要求后端已到齐的完整记录。以服务端持久入库序号排序，客户端时间不决定新旧。
- 结果到齐前不公开该轮；到齐时其最后一个组成记录的首次入库序号决定该轮顺序。重复上传不会改变顺序。
- 普通测试和复测、不同用户，完全遵循同一入库规则。晚到的旧任务结果也可以成为当前记录，但不能完成其他租约的任务。
- 当前成功率、失败分类、主性能以当前整条记录的 AF-MLIR 为准；不借用历史 AF-MLIR 结果。Unknown 也可替换旧结果。
- 同一 seed 固定图、权重、输入和全部 Shape 顺序；workload 指纹校验复现契约，不容许静默生成其他内容。
- 不改写任何历史 attempt、用户归属或错误证据。

## 2. 页面

服务端网站标题和顶栏品牌统一为“Autofuse一站式工作平台”，使用绿色融合节点 SVG 图标。桌面顶栏菜单靠左，更新时间和登录操作组成靠右区域，更新时间在登录左侧；窄屏换行适配。登录弹窗仅保留 Token 输入、错误提示和同一行的取消/登录按钮（取消在左，登录在右），不显示额外 Token 说明文案。

功能&精度列表默认每个 seed+Shape 一行，显示当前整条记录原有的所有字段。

- 多于一条记录时，最左侧显示小三角及数量，默认折叠；仅一条不显示三角。
- 展开后保留当前行，下面插入更早记录，不重复当前行。
- 历史记录按首次入库顺序倒序，使用同一组列/列宽/自定义列设置，仅用背景区分，不缩进。
- 用户、环境、时间及后端结果全部来自该行自己的测试轮次，不显示“多来源”拼接行。
- “时间”复用现有列：新数据显示服务器首次入库时间；旧数据无该时间时保留原记录时间并明确提示，不伪造历史时间。原客户端时间在详情中保留。
- 来源字段默认空，仅明确复测显示“复测”。不显示“普通测试”“未记录”。
- summary_id 和原因/解决方案仅在详情页，不出现在列表。
- 不增加批次/任务列；“我的复测”只负责任务进度和取消。
- 未登录隐藏选择框、复测及个人任务操作；公开结果和历史照常可读。

## 3. 筛选、分页、刷新

- 先选每个 seed+Shape 最新完整轮次，再执行所有筛选，包括状态、用户、版本和文本。不得先过滤历史再选最新。
- 展开历史不受当前行筛选条件裁剪，可看到过去 Pass/Fail。
- 每页 10 条指 10 个聚合组；历史行不占主分页名额。
- 历史按需分页加载，提供“加载更多”，不能全量下载或因历史超过 1000 条报错。
- 使用稳定入库游标和展开时的快照边界；新数据到达保留展开和选择状态，避免重复/漏行。
- 当前行变化后，旧当前行自然进入历史。旧异步请求不能覆盖新页面。
- 本期不实现搜索历史记录模式。
- 精确短 Seed 搜索在聚合入口收窄数据，不扫描全站；其他筛选仍先确定当前记录再过滤。全站重查询与后台预热共享单并发预算，忙时返回带 Retry-After 的 503，避免阻塞上传/续租。公共缓存保持上一次成功快照；后台首次全量回退允许最多 300 秒，交互查询不增加超时。

## 4. 测试轮次与存储

核心 attempts/shapes 保持不可变。已有来源、batch 和配置用于识别同次测试，不作为外层聚合维度。新客户端通过 round_id 明确标识同次执行，避免不同轮次的后端交错上报时错误拼接。旧数据没有 round_id 时，以原分组下各后端的入库次序匹配；缺少明确执行标识的历史记录无法完全还原乱序缺失场景，这是兼容边界，不推断不存在的执行事实。

新增持久入库信息保存 attempt 首次接收序号和服务端时间；历史回填只使用已存在的数据库顺序，服务器时间留空。重传 INSERT OR IGNORE，不改首次接收信息。

一个轮次完成条件：存在 AF-MLIR，且 expected_backends 声明的所有后端已到齐。未声明 expected_backends 的旧数据以已有后端集合为边界，以 AF-MLIR 首次入库序号决定新旧，避免旧轮次补传辅助后端挤掉更新结果；仍必须有 AF-MLIR。各轮输出按其自身实际 Shape 构成历史；共享准备失败不伪造成具体 Shape 结果，保持用例级失败明细；后续完整 Shape 序列到齐后不再将旧共享失败计入当前质量指标，原始详情保留。已知复测指纹/配置不匹配的上传保留证据和 ACK，但不参与当前结果投影。

列表、summary、statistics 共同使用相同的最新整轮查询；不再使用 retest_heads 定向覆盖或任务提交顺序覆盖。旧开发态投影表不作为当前结果依据。

所有执行事实供历史/资源统计使用；当前质量和性能查询仅使用当前轮次，不让历史重复实验扩大成功率分母。

### 结构化读取模型

原始 attempts、shapes、contexts 和诊断 JSON 保持权威、不可改写。显式执行 `maintenance index-cases` 创建可重建读取模型：

- `case_heads_v1`：seed + shape_index 唯一索引，保存当前完整轮次和历史数量；按 cursor、status + cursor 建索引。
- `case_history_v1`：历史完整轮次，索引为 seed + shape_index + cursor。
- `case_results_v1`：完整轮次各后端 Shape 的状态和失败路径，不携带完整执行日志。
- `case_projection_v1`：展开状态、用户、后端、模式、CANN/Torch/Autofuse 版本及搜索字段，保留原有筛选语义。
- `case_display_v1`：预计算功能分类、MLIR 路径/证据、错误摘要和脱敏运行日志，列表不再调用 Python 归因函数。
- `case_attempt_flat_v1`：模式、设备、诊断存在标记和移除诊断/遥测后的配置预览。
- `case_dimensions_flat_v1` / `case_dtypes_flat_v1`：按 workload + Shape 存储维度上限、元素数及去重 dtype。

入库事务完成原始写入后，只重建受影响 Seed 的读取模型；原始写入、模型更新、上传 ACK 同事务提交。源表触发器记录 dirty Seed，捕获直接更新、删除和迁移。模型有未处理变更或分类版本不匹配时，查询回退到旧的精确计算，不读取过期当前行。显式回填和版本升级在事务内切换，失败回滚。导入、清理和索引重建也维护读取模型；旧导出文件没有模型时继续兼容。

当前实现仍保留轻量统计临时表，以及详情按需读取原始 JSON。初次回填和受影响 Seed 的写入阶段仍需要解析/分类，不承诺消除所有 JSON 或临时表。验收必须比较新旧完整当前行、历史、筛选、统计和无公共响应缓存的真实查询时间。


## 5. 登录与复测

Token 换取有限期浏览器会话，Secure/HttpOnly/SameSite Cookie，同源和 CSRF 校验。长期 Token 不存 localStorage、URL 或日志；每次受保护请求校验身份和归属。

可复测任何人的公开成功或失败记录，但只调度自己的客户端。客户端配置 Token 且后台服务运行即默认接单，不增加启用开关。

批量选择支持当前页全选、跨页保留。相同 seed、执行/评估配置和目标客户端合并为一个完整用例任务；选中 S0/S1/S2 不重复执行三遍。提交前 preview 显示选择数与实际任务数。

每项网页复测执行 CPU 参考 + AF-MLIR；其他后端保持为明确附加能力，不在本期增加选择主后端。复测任务记录被选择的基准执行，用于追踪，不决定结果覆盖资格。

客户端每次最多领取 8 项，受队列空位约束；并发仍由现有资源池控制。共享现有 staged 队列，不启动竞争调度器、不抢占、不停止用户正在运行的随机任务。legacy 队列未结束时等待。

租约和 generation 保障任务归属、恢复和取消。结果本身只要合法首次上报就遵循全站入库规则；迟到/取消任务的结果保留事实，不能修改其他代次任务状态。断网重传不重复计数。

设备繁忙可有限等待；取消/掉线是任务状态，不伪造执行结果。已上报的合法 Unknown 结果也按最新记录展示。

## 验证期身份写入白名单

服务端可通过 `AF_FUZZ_WRITE_ALLOWLIST` 指定本机 JSON 配置文件。未设置时不限制；设置后必须成功读取、严格校验，错误则拒绝启动，不能静默放行。配置仅在启动时加载，不提供网页修改入口；启停限制需要重启 API，便于维护窗口审计。

配置包含 `enabled`、`users`（允许网页写入的用户 UUID）和 `clients`（`user_id` + `client_id` 对）。客户端 ID 即上传 source_id/复测 client_id。必须使用 Token 鉴权得到的用户身份配对，不能只相信请求声明的 ID，也不按 IP 识别。它不是新的客户端密钥机制：持有相同用户 Token 且复制相同 source_id 的进程无法由此区分。

- 结果上传、执行事实、心跳、注册、领取、续租和完成均检查用户与客户端配对；原有归属和租约检查仍执行。
- 网页提交、预览要求用户与目标客户端均获允许；取消要求用户获允许且原有任务归属检查通过。
- 登录、退出、公开查询和用户自己的只读查询不受限制。
- 拒绝返回 HTTP 503、`Retry-After: 60` 和固定维护错误码，不写入执行数据、不创建来源、不推进 ACK、不伪造成功。
- 客户端保留待上传结果并按现有重试周期重试；503 不触发复测消费端的永久鉴权失败处理。Retry-After 为提示，现有客户端不保证严格按 60 秒重试。
- 白名单不暂停远端已开始的执行，也不冻结现有租约时钟；维护前应停自己的正式任务，其他客户端的执行可能继续，租约可能到期。恢复后积压数据按首次入库顺序参与当前结果。
- 此阶段只交付代码与配置说明，不启用限制、不停止服务、不部署 oracle1。

## 6. 分析总结

复测结果明细预留 nullable summary_id，可跨多个用例共享一个总结。该字段是可后补元数据，不进入不可变执行哈希；不建立跨库外键。

详情：null 显示“暂无分析总结”；有 ID 但服务未接入显示“已关联总结，内容暂不可用”。本期不建总结库、不实现 agent 总结接口。

## 7. 开发与验收

1. 改写当前设计；完成查询/入库顺序迁移，不动身份、凭据、ACK。
2. 全站 seed+Shape 最新整轮及历史分页；统一统计、筛选、当前性能。
3. 复测执行矩阵固定包含 AF-MLIR；移除任务定向覆盖语义。
4. 三角展开、背景历史行、来源空/复测、时间列、批量选择和详情。
5. Docker API/数据库回归及 HTTPS 浏览器验证。
6. mlir 上软件回归与真实 AF-MLIR 双卡复测；检查占用，不干扰原任务。
7. 自测完成通知用户，由用户决策 oracle1 实测部署。本任务禁止自行部署 oracle1。

必测：跨用户普通上报覆盖、Pass↔Fail、完整轮次/部分上传、后端不跨轮拼接、ACK 重传、迟到结果、同 seed 多 Shape、先最新后筛选、历史加载更多/刷新状态、数千历史、入库时间回填、复测矩阵/任务恢复、权限/CSRF、summary_id 仅详情、统计与列表一致。
