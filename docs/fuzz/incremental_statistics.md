# 公共统计增量计算

## 范围与成本

无筛选公共统计不再因数据库有一次提交就重算全部历史。首次启动遍历现有用例组，之后通过源数据库事务内的 SQLite triggers 登记 group/window 变化；按组重新计算旧贡献并替换。原始结果、身份、ACK 均不修改。

- 默认后台每轮完成后休息 30 秒，失败退避最高 300 秒，沿用上一轮降载策略。
- 没有相关变化时重算 0 个组；无关表变化不触发统计 SQL。
- 一次重试只更新对应组，但会读取该组历史 attempts，以保留原统计中“最新结果决定质量、所有 attempts 计入耗时”的口径。
- 计数、sum、有效测量样本数按贡献增减；平均值不是平均各组均值。min/max 从带索引的组贡献取得，删掉原极值后会正确变化。
- 后端显示别名不改变原始 backend 的分组和输出顺序。
- 窗口统计只重算脏窗口；P50/P95 仍按窗口原算法计算，不合并分位数。页面仍取最新 100 个窗口。
- 有筛选的搜索/统计仍使用原实时查询。首页列表仍是原有有界候选窗口查询，不是增量统计的一部分。

## 一致性与恢复

源数据库新增 `public_changes_v1` 及触发器/索引，写入者与变更登记同一事务，不依赖某个上传入口。覆盖 attempts、shapes、reporting facts、metadata、stage facts、lifecycle、窗口及窗口聚合的新增/修改/删除，额外处理 REPLACE 的旧组/旧窗口。

派生文件为 `results.sqlite.public.sqlite`，权限 0600。只包含统计贡献、待处理组、窗口摘要和 checkpoint，不复制用户凭据。重算时源库只读；派生文件在独立事务中一起提交贡献、pending 和 checkpoint，提交后再清理已消费源 journal。新提交的序号高于读快照水位，不会误删；中途失败会回滚当前批次。

首次建索引每批最多 64 项，批次工作约 2 秒后让出；一轮约 20 秒后可保存进度并等待下一轮（单项 SQL 另有 30 秒上限）。服务关闭在批次间终止。数据库文件更换 inode 或派生格式版本变化会重新建立派生状态。显式覆盖同 inode 的备份恢复后应移开派生文件重建，不能把旧派生文件混用于另一个数据库。

## 验证与发布状态

本地回归覆盖新增、重试、重复上传、删除、REPLACE、metadata 更新、迟到阶段事实、窗口汇总、NULL 测量、极值替换、事务回滚、重启、失败恢复、并发提交、源库替换和有界 bootstrap。

与修改前 HEAD 全量统计对照：120 attempts / 40 groups，初始化及重试后的完整 JSON 相同。

本地合成 1,000 组测试：全量约 8.3ms，首次增量建索引约 1.14s，无变化约 1.9ms，单组重试约 3.3ms、重算组数 1。该数据没有线上宽日志和低配宿主机干扰，不能当线上性能承诺；首次建索引比一次全量扫描更慢是预期的持久化构建成本。
